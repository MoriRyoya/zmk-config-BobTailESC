# BobTailBar — macOS メニューバー常駐アプリ

CodexBar と同じく、**設定からメニューバーに出す項目を選べます**。レイヤー表示・左右バッテリー・キーマップ確認・ジェスチャの感度もここから変えます。

---

## インストール

```bash
cd tools/macos/BobTailBar
./build.sh install
```

起動後、**システム設定 → プライバシーとセキュリティ** で次を許可し、アプリを再起動してください。
2 つは対等ではありません。

| 項目 | 用途 | 無いとどうなるか |
| --- | --- | --- |
| **入力監視**（必須） | レイヤー通知（Num/Sym/Gesture/Fn/Mac/Win/Scroll）を IOHID で読む | **他アプリではレイヤー表示が一切追従しません**（BobTailBar を選んでいるときしか更新されない） |
| アクセシビリティ（補助） | 実際に打っているキーをオーバーレイに反映する（レイヤーの入り口キー以外のハイライト用） | 打ったキーが他アプリでは光らない。レイヤー表示自体は入力監視だけで動く |
| Bluetooth | 左右のバッテリー残量 | 残量が出ない |

レイヤー通知は「□?」のような文字化けを起こさないよう、どれも macOS がキーイベントを
組み立てない HID コードで送っています（詳しくは後述）。その代わり、これを読めるのは
IOHID（＝入力監視の許可）だけなので、**入力監視が無いとレイヤー表示は完全に止まります**。
アクセシビリティだけ許可してもレイヤー表示は直りません。

メニューの「キー監視」が赤くなっていたらどちらか（主に入力監視）が足りない状態です。
**この赤い行自体をクリックする**か、重ね表示の右上に出る赤い警告文をクリックすると、
足りない方の設定パネルがそのまま開きます（両方欠けているときは入力監視から）。
メニューの「入力監視 / アクセシビリティを許可する…」からも同じ場所へ行けます。

### 再ビルドすると許可が外れる場合

macOS は署名が変わったアプリの許可を捨てます。ad-hoc 署名（`-`）はビルドのたびに
署名が変わるので、`./build.sh install` するたびに許可し直しになります。GitHub トークンを
Keychain に保存している場合も同じ理由で毎回読めなくなり、設定画面に入力し直しになります。

キーチェーンアクセスで **「BobTailBar Local」** という名前のコード署名用の自己署名証明書を
作っておくと、`ensure-signing-identity.sh` がそれを拾って毎回同じ署名でビルドします。
`Apple Development:` の証明書があればそちらが優先されます。

## メニュー

クリックすると次が出ます。

| 項目 | 内容 |
| --- | --- |
| レイヤーでキーマップを表示 ⌘K | 現在レイヤーの配列を半透明で重ねる（オン / オフ） |
| 入力監視 / アクセシビリティを許可する… | 足りない許可があるときだけ出ます（入力監視が優先） |
| 設定… ⌘, | 表示・キーボード・キーマップ・ジェスチャ・スクロール・一般 |
| トラックボールジェスチャ | 一時的にオン / オフ |
| バッテリーを再取得 | BLE を読み直す |

## 設定

### メニューバー

チェックで表示 / 非表示、上へ / 下へで順番です。

- レイヤー（ABC / 123 / SYM / GES / FN / SCR / WIN）
- OS モード（mac / win）
- 左バッテリー %
- 右バッテリー %
- 少ない方のバッテリー %
- ジェスチャ状態

区切り文字と L/R プレフィックス、文字サイズも変えられます。プレビューが上部に出ます。

ベース以外のレイヤーを保持している間、メニューバーの文字がレイヤー中の色（既定はアクセントカラー）になります。
メニューを開かなくても、別の層に居ることが視界の端で分かります。この色は「キーマップ」タブで変えられます。
バッテリーはメニュー内で残量バー付きになり、30% 以下で橙、15% 以下で赤になります。

### キーボード

- **キーボードに追従** … Fn 層の Mac / Win キー（Consumer 0x01D4 / 0x01D5）に合わせる
- **macOS 表示に固定** / **Windows 表示に固定** … キーマップ確認とバッジだけアプリ側で切り替える

本体の Win 層そのものは ZMK 側のキーで切り替わります。アプリから HID でファームウェアのレイヤーを書き換えることはできません。

### キーマップ

レイヤーキーを押すと、その配列が画面に重なります。AML も本体の通知に追従して表示します。**設定ウィンドウを開いておく必要はありません**。
設定の「キーマップ」タブにも同じ配列のプレビューが出ます。

- 透明度はスライダーで 25%〜100%
- 大きさは四隅のどこからでもドラッグして変えられます。Shift または Command を押しながら操作すると縦横比を保ちます（設定のスライダーでも可）
- 位置は上の帯をドラッグ。四隅へ一発で寄せるボタンもあります
- クリック透過をオンにすると、重ねたまま他のアプリを操作できます（上の帯と四隅だけ掴めます）
- 「ベース（ABC）では隠す」を切ると出しっぱなしにできます
- レイヤーへ入るキー自体（Space・かな・専用 Fn など）は常に光ります。**それ以外の押しているキーも
  強調表示する** をオンにすると、実際に打っているキーも合わせて光らせられます
- **押しているキーの色** と **レイヤー中の色** はそれぞれ色を選べます。「既定に戻す」で
  システムのアクセントカラーに追従する状態へ戻ります。押しているキーの色は文字色（黒 / 白）を
  自動で選ぶので、暗い色を選んでも明るい色を選んでも読めます
- **読み込み先** で配列の出典を選べます
  - **自動 / フォルダ** … ローカルの `config/BobTail.keymap` を監視し、Keymap Editor の保存をすぐ反映
  - **GitHub** … リポジトリ（`owner/repo` か URL）を指定。ブランチ初期値は `feature/researcher-keymap`。公開はトークン不要。非公開は Fine-grained token（Contents: Read）を入れると GitHub API 経由で読めます。約 20 秒ごとに取り込みます。トークンは plist ではなく Keychain に保存されます
  - **アプリ内蔵** … ビルド時に同梱した `config/BobTail.keymap` そのもの

配列と発光位置は同じ `.keymap` の出力を読んで決めます。数字配置の固定表は廃止しました。
`LEFT_BRACE` は `{`、`LEFT_BRACKET` は `[` のように表示し、透過キーも実際の下位層へ解決します。
通常のHIDは物理スイッチ位置ではなく出力キーを通知するため、同一の出力を複数位置に置いた場合は
一意に識別できません。曖昧な位置は推測して複数点灯させません。入力中に層を離しても、キーを離すまでは
押下時の位置を保持します。GitHubの変更を表示しても、本体へのファームウェア書き込みは別途必要です。

左右バッテリーは同一UUIDを別々の値として保持し、接続前・切断・読取失敗時は `—` を表示します。
詳しい修正と電圧換算の制約は [バッテリー説明](../../docs/battery.md) を参照してください。

### ジェスチャ

オン / オフは、古いホスト側変換用です。ボールの Mission Control などはファームウェアが担当するので、通常はオフで構いません。

### スクロール

BobTail のホイール入力をピクセル単位で補間し、弾いた後だけ減速させます。

| 設定 | 標準 | 範囲 |
| --- | --- | --- |
| 滑らかさ | オン | オン / オフ |
| 速度 | 1倍（1 目盛り = 48 px） | 0.25〜3倍 |
| 慣性 | 50%（= 旧ファームウェアと同じ） | 0〜100%（0なら慣性なし） |
| 応答 | 24 ms | 10〜80 ms（短いほど即応） |

計算はピクセルではなく **目盛り**（`CONFIG_PMW3610_SCROLL_TICK` 1 個ぶんのボール移動）で行います。
慣性50% は、ファームウェアの `CONFIG_PMW3610_SCROLL_MOMENTUM` が持っていた減速そのままです
（16 ms から始めて 1 目盛りごとに 30% 間隔を伸ばし、100 ms を超えたら止める = 約 6 目盛り / 0.28 秒）。
つまみは 0%（流れない）から 100%（約 15 目盛り / 0.83 秒）まで、
5 目盛り未満のスクロールはどの設定でも流れません。効きが速度の設定に左右されることもありません。

新しいファームウェアは本体側の慣性を無効にしています。旧ファームウェアのままだと慣性が重なるため、
左右を更新してから利用してください。
**アクセシビリティと入力監視の両方**が必要です。前者は CGEvent タップでホイールを差し替えるため、
後者は IOHID で「BobTail のホイールだ」と確認するためで、片方でも欠けると慣性は黙って素通しになります。
メニューの「キー監視」の行に、いま何が足りないかが出ます。
Macトラックパッドの連続入力は通過させ、BobTailのHIDホイール入力と時間・軸が対応するものだけを補間します。
ポインタ移動・クリック・打鍵・切断などで残りの慣性を止めます。

### 一般

ログイン時起動。

## 重ね表示のしくみ

配列は AppKit で直接描いています。列ごとの縦のずれ（カラムスタッガー）も実機に合わせてあり、
中指の列がいちばん奥、小指と内側の列が手前に来ます。ずれ量は `KeymapView.swift` の
`KeymapGeometry.columnStagger` にまとめてあるので、手元と違って見えるならそこだけ直せます。

以前は `docs/keymap.html` を WKWebView に載せていましたが、LSUIElement のアプリでパネルを隠すと
macOS が WebKit のコンテンツプロセスを止めてしまい、**設定ウィンドウを開いてアプリを前面に出すまで
レイヤーを切り替えても配列が変わらない**という問題がありました。透明度を 0.02 にして隠したことにする、
定期的にアプリを activate する、といった回避策は症状を薄めるだけで、そのうえユーザーが打っていた
アプリからフォーカスを奪っていました。

自前で描けば止まるプロセスがありません。パネルは `.nonactivatingPanel` なので前面に出てもフォーカスを
奪わず、押した瞬間に描き直され、ライト / ダークにも追従します。

## レイヤー通知（ファームウェア側）

キーボードは各レイヤーを保持している間、専用の HID コードを送り続けます。
BobTailBar はこれを読んでレイヤー表示を切り替えます。

以前は F13 / F16–F20 という「Fn キー」を使っていましたが、これらは Apple の
キーボードにも仮想キーコードが割り当てられた本物のキーで、macOS が実際に
keyDown イベントを組み立てます。BobTailBar のタップが止まっている一瞬
（アクセシビリティが外れた直後、再接続中など）はこれを飲み込めず、前面の
アプリへ生の入力として漏れ、環境によっては「□?」のような文字化けが入力
されることがありました。

今は Scroll（F22）以外すべて、USB HID Usage Tables の Consumer ページで
未割り当てのまま空いているコード（0x01D0–0x01D6）を使っています。Apple の
どのキーボードもここに対応する仮想キーコードを持たないため、macOS が
そもそも keyDown イベントを組み立てません。BobTailBar が止まっていても、
そもそも文字として現れようがない仕組みです。F22 が昔から同じ問題を
起こしていなかったのも同じ理由です（Help キーだと Finder がカーソル下の
項目を選択してしまうため、あえて対応する仮想キーコードの無い F22 を使って
います）。

| 通知 | HID コード |
| --- | --- |
| Num+Nav | Consumer 0x01D0 |
| Sym | Consumer 0x01D1 |
| Gesture | Consumer 0x01D2 |
| Fn | Consumer 0x01D3 |
| macOS モード | Consumer 0x01D4 |
| Windows モード | Consumer 0x01D5 |
| AML (Mouse) | Consumer 0x01D6（本体のレイヤー状態から通知） |
| Scroll | Keyboard F22（旧ファームウェアは Help） |

キー操作の通知を止める場合は `config/BobTail.keymap` の `LAYER_INDICATOR` を `0` にします。
AML通知は `pmw3610/src/bobtail_status.c` で独立して送っています。

## 検証

```bash
bash tools/macos/test.sh
python3 -m unittest discover -s tools -p 'test_*.py'
```

四隅リサイズ、読み込み配列と数字・記号の発光、AMLの優先順位、バッテリーの非同期取得、
スクロールの移動量保存・減速・キャンセルを検証します。実機の感触とBLE再接続は別途確認が必要です。
